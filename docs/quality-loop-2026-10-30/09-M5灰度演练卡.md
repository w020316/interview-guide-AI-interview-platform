## D0 · 建表核查（2026-10-31 首次演练时发现并修复了一个 P0）

> **结论：`ai_task` 表此前在生产根本不存在。** 这条是演练的第一个战果——如果不做演练直接开开关，用户看到的是全线 500。

| 项 | 内容 |
|---|---|
| 现象 | `GET /api/tasks` 返回 `{"code":500,"message":"数据库操作失败，请联系管理员"}` |
| 根因 | `CREATE TABLE ai_task` 只写进了 `schema.sql`，没进 `SchemaInitializer.DDL_LIST`；而 prod 是 `sql.init.mode=never` + `ddl-auto=none` → 生产库从未建过这张表 |

| 修复 | `291d977`：补 DDL + 纳入 `REQUIRED_TABLES` 启动自检 + 新增 `SchemaDdlCoverageTest` 门禁（扫实体自动发现，变异测试验证过会红） |
| 复核 | 部署后 `GET /api/tasks` 由 500 → 200（2026-10-31 12:40 实测），指纹成立 |

## 2026-10-31 演练发现（第二轮）

### 阻断项：P1-3「重新生成」没有真正换题

- 现象：同一简历/岗位下，点「重新生成」会新建 task（幂等键已掺随机量，task 4 确实创建并成功），
  但题目与 task 3 **逐字相同**。
- 根因：`regenerate` 只参与了**任务幂等键**，没有进入 `payload`，也没有进入
  `InterviewService.generateQuestions` 的缓存 key。该缓存 TTL 1 小时，key 只含
  `userId + resumeText + jobDescription + count + difficulty + focusCategories`
  （见 `InterviewService.java` 的 `QUESTION_CACHE` 段），因此新任务直接命中旧结果。
- 修复方向：把 `regenerate` 透传到任务 payload 与 `generateQuestions`；
  `regenerate=true` 时跳过缓存读取（可用一次性 nonce 参与 key），确保真的发起一次新的 AI 调用。
  同步回退 `/api/interview/questions` 也需要接受同名字段，否则开关关闭时重新生成同样会拿回旧题。

### 前端边角：同一页面点「重新生成」无效

- 现象：已经处于 `/interview?taskId=3` 时，从抽屉点「重新生成」只改了 query，
  组件不会重新挂载，`recoverFromTask` 不会执行，界面无任何变化、也不发请求。
- 根因：`InterviewView.vue` 的恢复逻辑只在 `onMounted` 里读 `route.query.taskId/regenerate`，
  没有监听 query 变化。
- 修复方向：监听 `route.query` 的 `taskId/regenerate`（或抽屉点击时先跳走再跳回），
  确保 query-only 导航也能触发恢复/重新生成。

### 本轮部署方式（无 Render 凭据）

- 用 `backend/Dockerfile` 的 ENTRYPOINT 加 `-Dapp.task-center.enabled=true` 打开开关
  （JVM 系统属性优先级高于环境变量），提交 `5e99d05`；演练后 `6a0b9d6` 已还原并上线。
- 部署是否真的发生，用 GitHub Deployments 判定（无需 Render 登录）：
  `gh api repos/w020316/interview-guide-AI-interview-platform/deployments`。
  本轮三次部署（开、复演前、回滚）均 `success`。

☑ **可开启** ☐ 需修复后再演练

**开启动作（2026-10-31 已执行仓库侧）**：

1. `render.yaml` 的 `APP_TASK_CENTER_ENABLED` 已改为 `true`；`application.yml` 默认值仍保持 `false`（新环境漏配时自动退回同步出题，不会不可用）。
2. 打开开关**必须**在 Render → Blueprint 点一次 `Sync`（普通 auto-deploy 不会重写环境变量），会触发一次重启，冷启动 3–8 分钟。

4. 若需紧急关闭：把本项改回 `false` 并再次 Sync，或直接在 Render 面板改环境变量（注意面板改动会造成仓库漂移，事后要回写 `render.yaml`）。

### 观察项（不阻断开启）

1. **开关关闭时 `/api/tasks/summary` 返回 503 属设计**：`AiTaskController.summary()` 显式受 `enabled` 门控；列表/详情/取消不受影响。演练时勿按缺陷记。
2. **抽屉列表不会自动刷新**：同页重新生成成功后，抽屉里仍是旧快照，重新打开才拉新列表。小体验问题，不影响正确性。
3. **偶发一次空结果分支**：复演中有一次点击在 9.2s 后提示「重新生成失败，请稍后再试」（未取到当次响应体）；随后同路径复测 200 + 合法数组 + 成功。同步链路一直使用严格 `safeParse`，与任务中心无关，属 AI 输出格式偶发不稳定的既有风险；后续可考虑复用 `JobAnalysisView.repairAndParse` 的宽松解析。
4. **验证环境陷阱**：Render 重启后调试 Edge 可能保留到旧实例的连接，表现为页面内请求永久挂起而 `curl` 正常；重启调试浏览器即恢复。排查时先用 `curl` 对照，避免误判为产品缺陷。
