## 1. 全局执行纪律（不变式）

1. **分阶段串行**：阶段一至阶段五依次执行，每阶段产出报告并等待确认；未确认不进入下一阶段。
2. **数据真实性**：未实测的数字写「待基线」；GitHub star、CVE、设计参考等外部数据联网核实并附官方来源链接。
3. **一问题一 commit**：`类型(范围): 简短描述`，body 必须含「问题 / 思路 / 验证」三要素。
4. **测试纪律**：每个修复跑对应模块专项 + 全量回归；禁止改断言、删失败用例、调阈值换绿灯。
5. **修复上限**：P0/P1 100%；P2 ≥90%；P3 进 backlog。阶段三/四新发现的 P0/P1 就地修复，不拖到阶段五。
6. **零生产写入**：阶段三/四的功能走查使用本地 `local` profile（H2）+ 本地构建产物；生产只做只读冒烟与性能采样。
7. **成本纪律**：不主动探测 Render 健康；线上复验按批聚合；不修改保活窗口与额度守卫。
8. **不掩盖**：无法验证的项（Safari、真实用户样本、AI 质量）明确标注边界，不用「已覆盖」措辞。

### 阶段四 · 真实用户体验全链路评估

**目标**：以真实用户视角走通 3 条核心链路，量化体验与性能，形成改进建议与 roadmap。

| 场景 | 路径 |
|---|---|
| S1 简历闭环 | 注册 → 登录 → 上传/粘贴简历 → AI 分析 → 四维评分与建议 → 历史回看 → 对比/导出 |
| S2 面试闭环 | 创建面试会话 → 生成题目 → 逐题作答 → 提交评分 → 结束会话 → 复盘报告 → 导出/分享 |
| S3 求职闭环 | 招聘广场多条件筛选 → 收藏/加入投递台账 → 人工确认投递 → 生成定制简历要点 → 日历跟进 |

**采集**

- 每步操作耗时、跳转路径、接口响应时间；首屏 FCP/LCP、INP、CLS（模板写 FID，已废弃，改用 INP 并注明）。
- 问题点：功能异常、操作繁琐、反馈不及时、文案不清晰；记录时间戳与稳定重现步骤。
- 每场景至少 2 张关键截图；关键接口请求/响应证据。
- 任务完成率（按关键步骤成功率计算）；SUS 十项评估（默认专家自评基线，明确样本性质）。

**预估**：3–4 小时。**通过标准**：3 场景可复现；指标有原始记录；建议可落地且不超出技术栈。

### 阶段五 · 系统性设计与体验优化

**目标**：按 8 个维度做 3 轮「测量 → 改 → 复测」，全站达到可验证的 9 分档，不留明显提升空间。

| 维度 | 量化口径 |
|---|---|
| 1 排版设计 | 字号阶梯、最小字号、亚像素字号、字族使用、行高、标题层级 |
| 2 留白运用 | 区块间距是否落在 4/8px 栅格；页面级留白三档；密度与内容匹配 |
| 3 视觉层级 | h1–h6 序列、每页 h1 数量、主 CTA 唯一性、信息权重 |
| 4 色彩系统 | 令牌唯一来源、WCAG AA 对比度、暗色一致性、强调色面积 ≤10% |
| 5 动效设计 | 过渡是否触发布局、时长 ≤500ms、60fps、`prefers-reduced-motion` |
| 6 微交互 | 悬停/按压/焦点/禁用/加载反馈、命中区、无响应元素 |
| 7 响应式表现 | 7 个断点无溢出/截断/功能缺失；移动端触控 ≥48px |
| 8 原创性 | 设计推导可追溯、无获奖作品直接复制、反模式清单逐条核对 |

**执行要求**

- 设计参考联网检索并附官方链接（Material 3、IBM Carbon、GitHub Primer、Apple HIG；Awwwards/Webby/FWA 评审口径），只提炼契合现有 Vue/Element Plus 栈的原则，不引入新框架。
- 令牌只改 `frontend/src/styles/variables.css`；组件规范落到 `BaseButton` / `BaseInput` / 卡片 / 弹窗 / 空态；**不新增断点**（白名单 `{480,640,768,960,1023,1180}` / `min-width:1024`）。
- 所有改动过 `designGuards.test.ts`、`changelog.test.ts` 与全量回归。
- 评分用可复现证据表，不以主观印象打分；未达 9 分的维度记录差距并继续迭代，不虚报。
- 优化后用阶段四**完全相同**的场景复测，输出前后对比；功能完整性不得下降。

**产出**：`05-设计规范.md` + 可运行代码 + 前后对比数据 + 8 维度评分表。

**预估**：4–6 小时（3 轮）。**通过标准**：8 维度均有证据与评分；目标 ≥9.0；全量回归绿。

**6A 调研与对标**

- 对象：3–5 个同类高质量开源项目（AI 模拟面试 / 求职辅助 / 简历分析），优先 star > 5k、近 3 个月有活跃提交。
- 每个项目核实：star、许可证、最近提交、技术栈、功能矩阵、部署复杂度；外部数据附官方链接。
- 输出：功能对比表 + SWOT + 1–5 分量化评分 + 「本产品已有 / 可补齐 / 不应做」三列结论。
- 对标来源同时包括阶段一的功能缺口清单与阶段四的新功能建议，避免重复造轮子。

**6B 功能完善落地**

- 从「可补齐」清单中按「用户价值 × 实现成本 × 与现有栈兼容性」选 2–3 项，先提交技术方案评审（范围、接口、数据/DDL、风险）。
- 评审通过后：独立 commit 实现 → 单测/全量回归 → 更新 changelog/版本 → 按阶段推送并线上复验。
- 不为了「功能看起来多」而引入需要新基建（邮件、推送、付费服务）的重功能；这类只进 backlog。
- 若调研结论是「当前无高价值缺口」，如实给出结论，不为凑数强行加功能。

**产出**：`06-阶段六调研.md`（含调研、评分、评审结论、落地记录）。

**预估**：调研 2–3 小时；落地按选中的功能另计。**通过标准**：外部数据可核实；方案与现有栈兼容；落地功能有测试与线上复验；用户确认范围。
