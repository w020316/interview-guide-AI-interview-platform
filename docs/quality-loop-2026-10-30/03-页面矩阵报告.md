| 登录态 | 通过 `localStorage` 注入（token/username/theme），未走登录表单 UI |

### 1.1 采集的机器判据（每页每视口）

1. `documentElement.scrollWidth > innerWidth` → 横向溢出；溢出时记录越界元素（排除 `position:fixed`）；
2. 可见交互元素（`a/button/[role=button]/input/select/textarea/.el-button`）尺寸 < 48×48（checkbox/radio 取包裹 label 尺寸）；
3. 叶子文本节点 `overflow:hidden` 且 `scrollWidth > clientWidth` → 文字被裁剪；
4. 文本对比度（WCAG 2.1 AA：正文 4.5 / 大字 3.0），背景无法静态判定（渐变/图片/半透明）时跳过，避免误报；
5. 页头高度/可见性、`[data-load-error]`、`[data-route-error]`、空态标记、页面总高度；
6. 控制台 error 与 ≥400 响应（同源后端请求）。

### 1.2 必须如实标注的边界

- **前端跑的是 dev server，不是生产构建产物**。`vite build` 的产物已在阶段一验证可用，但本轮的布局/断点结论来自 dev server；生产构建的样式差异（顺序与压缩）未逐页复验。
- **仅 Chromium**。Firefox / Safari 的两个最新正式版未覆盖（无可用自动化环境，未联网安装），按规则标注为「未测」，不得据此推断兼容性结论。
- **无 AI Key**：AI 生成类页面只验初始态/空态/结构，不验生成结果与流式过程。
- **加载态（loading）未采样**：本地后端响应过快，未做网络限速；该项留到阶段四真实链路观察。
- 深色模式为「全量路由 × 3 档视口」，不是 7 档；未覆盖的 4 档按「浅色已验证布局 + 深色 0 高度差」推断，不作额外结论。

## 3. 逐维度检查结果

### 3.1 布局与溢出 —— 通过

302 组采集**无一组出现横向滚动条**，也未见元素越出视口右边界。长页面（`/jobs` 全页 4237px、首页 2550px、`/resume/studio` 2143px、`/admin` 1816px）在 375 宽下均能正常折行堆叠，未出现卡片挤压或栅格塌陷。

### 3.2 导航 —— 通过

- 桌面端 1920/1440/1366：顶部主导航 + 「求职工具」下拉完整可见，无换行溢出；

### 3.3 明暗模式一致性 —— 通过（附 1 条对比度问题）

- 同路由同视口下，深色与浅色页面总高度**差值全部 ≤2px**（69 组对比，0 组超阈值），说明深色切换未引起布局跳动；
