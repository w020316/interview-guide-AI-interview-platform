## 2. 场景一：新用户注册 → 粘贴简历 → AI 分析 → 结果

**路径**：`/login`（注册 Tab）→ 提交 → 自动登录回首页 → `/resume` → 切「粘贴文本」→ 填简历 + 目标岗位 → 开始分析 → 四维报告

| 步骤 | 耗时 | 结果 |
|---|---:|---|
| 打开登录页 | 589ms | 表单完整，Tab 切换清晰 |
| 填表并提交注册 | 804ms | 成功后自动登录，落地 `/`，`token` 已写入 |
| 打开简历分析页 | 227ms | — |
| 粘贴简历 + 选岗位 + 点「开始分析」 | 1778ms | 骨架屏立即出现（4 卡 + 圆形占位） |
| 等待 AI 返回 | **20982ms**（首轮全链为 6141ms） | 四维分数 82/78/76/80 + 每条 AI 建议 |

**体验要点（正面）**
- 注册表单有实时校验、密码规则提示；提交后无需再登录，直接回首页（少一步）。
- 分析等待期有**骨架屏 + 分步文案**（「AI 正在分析你的简历 · 首次调用需冷启动，最长约 1-2 分钟」），等待焦虑被显著缓冲。
- 结果不是单一总分，而是「维度 + 问题 + 建议」三段结构，可直接拿去改简历。

**体验要点（问题）**
- 21s 等待中没有任何**进度百分比或剩余时间**，只有静态文案；用户无法判断「还要等多久/是不是卡住了」。
- 报告未提示「是否已保存到历史」；用户需自己发现 `/resume/history`。

**佐证**：[`登录`](./raw/screens/ux/s1-onboarding-resume-login-2026-10-30T10-42-26.png)、[`填写`](./raw/screens/ux/s1-onboarding-resume-resume-filled-2026-10-30T10-42-26.png)、[`加载骨架`](./raw/screens/ux/s1-onboarding-resume-resume-loading-2026-10-30T10-42-26.png)、[`结果`](./raw/screens/ux/s1-onboarding-resume-resume-result-2026-10-30T10-42-26.png)

## 3. 场景二：找工作 → 搜索 → 岗位详情 → 加入投递计划 → 投递台账

**路径**：`/jobs` → 关键词「Java」→ 搜索 → 点岗位卡片（抽屉）→「加入投递计划」→「查看完整详情页」→ `/jobs/518` → `/applications`

| 步骤 | 耗时 | 结果 |
|---|---:|---|
| 打开招聘广场 | 2563ms | 列表渲染，筛选 chips 带计数 |
| 关键词搜索 | 1657ms | 结果刷新 |
| 打开岗位抽屉 | 1066ms | 摘要 + 内容体检 + 来源说明 |
| 加入投递计划（抽屉内） | 1737ms | Toast「已加入投递计划，可在『投递看板』跟踪进度」 |
| 打开完整岗位详情页 | 1209ms | `/jobs/518`，JD 完整保留换行 |
| 查看投递看板 | 1394ms | 投递总数 1、待投递 1，漏斗洞察出现 |

**体验要点（正面）**
- 抽屉里同时给出「前往官方申请入口 / 加入投递计划 / 查看完整详情页」，三类动作区分清楚，「不代替你投递」的定位有明示。
- 加入计划后立刻告诉用户去哪里看结果（Toast 带目标页名称），闭环感强。
- 详情页把「岗位标签 / 岗位描述 / 任职要求」分块呈现，长 JD 不挤成一段。

**体验要点（问题）**
- **详情页没有任何操作入口**：既无「收藏」，也无「加入投递计划」（实测 `detailHasPlan=0`、`detailHasFavorite=0`）。用户从抽屉跳详情后想收藏/入台账，只能返回列表或重新开抽屉 —— 这是一个明确的流程断点。
- 详情页只能「返回招聘广场」，没有「相关岗位 / 同公司其他岗位」，单页终点感较强。

## 4. 场景三：模拟面试 → 逐题作答 → AI 评分 → 结束 → 复盘/历史

**路径**：`/interview` → 填岗位 + 3 题 → 开始 → 逐题作答/提交 → 评分 → 下一题 → 结束面试 → `/history`

| 步骤 | 耗时 | 结果 |
|---|---:|---|
| 打开模拟面试 | 687ms | 表单 + 难度偏好 |
| 填岗位、改题数、开始 | 198ms | — |
| **等待题目生成** | **107899ms**（接口 `POST /api/interview/questions` 77095ms） | 3 题生成完成，分步进度可见 |
| 回答第 1/2/3 题 | 73 / 85 / 85ms | 输入即时 |
| **提交并等待评估 ×3** | **13270 / 26514 / 28547ms**（接口 11575 / 24881 / 26894ms） | 三维评分 + 改进建议 |
| 切到下一题 ×2 | 850 / 876ms | 正常 |
| 查看历史 | 1385ms | 会话状态「已完成」，有查看题目/复盘报告/删除 |

**评分样例**（第 1 题）：综合 15 / 完整性 10 / 准确性 15 / 表达力 20，并给出「聚焦题目，直接说明区别」「学习 Spring 注解」等改进项。

**体验要点（正面）**
- 出题期有**分步骤进度条**（连接后端 → 分析历史成绩 → AI 生成题目 → 保存题目），不是纯转圈。
- 每题评估后立即回填分数与改进建议，且「下一题 / 跳过本题 / 深挖提问」动作齐全。
- 结束面试后会话落库为「已完成」，历史卡片可查看题目与复盘报告，数据不丢。

**体验要点（问题）**
- **出题 108 秒**、单次评分 13–29 秒；三题综合下来，一次 3 题面试约 **3 分钟纯等待**。默认建议 5 题，按此推算会更久。
- **评分失败反馈重复且无显式重试**：首轮失败时同时出现「AI 服务暂时不可用，请稍后重试」（顶部）与「作答评分失败 Request failed with status code 503」（右下），用户需自己意识到「再点一次提交回答」可重试。
- **续做定位错位**：从历史点「继续作答」（或直接 `?sessionId=`）后，页面回到**第 1 题**且答题框为空，而服务端已有 3 题作答记录 —— 与代码注释声明的「自动定位到第一道未作答的题」不一致。
- **结束面试不弹复盘报告**：从历史续做后结束（`sessionEvals` 仅统计本页作答，为空），只显示「面试结束，结果已保存！」，复盘报告被隐藏，需回历史再点一次。

**佐证**：[`配置`](./raw/screens/ux/s3-interview-loop-interview-configured-2026-10-30T10-46-24.png)、[`作答`](./raw/screens/ux/s3-interview-loop-answer-1-2026-10-30T10-46-24.png)、[`评分`](./raw/screens/ux/s3-interview-loop-eval-1-2026-10-30T10-46-24.png)、[`续做落点`](./raw/screens/ux/resume-by-url.png)、[`结束后页面`](./raw/screens/ux/report-panel.png)、[`历史`](./raw/screens/ux/history-after-finish.png)

## 7. 关键事件记录（首轮全链路 AI 故障）

- **时间**：2026-10-30 18:42–18:43
- **现象**：`POST /api/interview/evaluate` 返回 503；页面提示「AI 服务暂时不可用」+「作答评分失败」；答案与输入未丢失（P2-16 修复生效）。
- **后端证据**：`AI 降级链全部失败（共 4 个节点）`，末位摘要 `zhipu-lastresort/glm-4-flash → 400 − 1211 模型不存在`；Agnes 两次退避重试均 429。
- **归因**：外部配额 + **末位模型配置失效**（E-08）。重试一次后（仅 NVIDIA 单节点）三题评分全部成功。
- **结论**：这是环境与配置叠加事件，不是随机故障；修复 E-08 后可恢复「四层兜底」的设计意图。

## 11. 功能完善度评估结论

- **主链路完整度**：三条核心链路均可走通并产出可见结果（简历四维报告 / 投递台账记录 / 面试评分与已完成会话），**无功能阻挡**。
- **待完善点**：详情页动作缺失（E-01）、断点续面语义不准（E-02）、复盘报告触发条件（E-03）—— 三者都属于「已实现但闭环差一步」，修复成本低、收益高。
- **外部依赖风险**：AI 质量与时延强依赖提供方配额；本轮免费档已多次触发 429/1305，生产需保证主力节点配额，并修复末尾兜底模型。
- **不纳入本轮结论**：AI 产出质量（评分是否准确、建议是否有用）需要独立评测集，本轮只记录「有输出、结构正确」，不做质量打分。
