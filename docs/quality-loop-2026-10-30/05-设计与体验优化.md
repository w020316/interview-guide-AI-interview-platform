## 3. 8 维度证据表

### 3.1 排版设计（9/10）

- 字号：`12/13/15/16/18/20/24/30/36/44` 十档全部定义在 `variables.css`，组件只引用令牌；
- 字族分工有明确规则（`--font-display` 衬线仅用于 ≥24px 页面标题；`--font-title` 用于无衬线标题；`--font-sans` 正文）；
- 采集 302 组页面**无文字裁剪**（`overflow:hidden` 且 `scrollWidth > clientWidth` 命中 0）。

### 3.2 留白运用（9/10）

- 间距只取 `4/8/16/24/40/64/96`；页面容器统一 900（阅读/编辑列）与 1080（宽页），外壳 1280，由 `designGuards` 强制。

### 3.3 视觉层级（9/10）

- 页面 H1（26px/700）→ 区块标题（16px/600）→ 正文（14–15px）层级连续；
- 品牌色只用于主行动与当前态（导航 active、主按钮），强调色（赭石橙）只用于「分数/提醒」等关键结果。

### 3.4 色彩系统（10/10）

- 浅色与深色各一套令牌，语义色全部成对（`--c-danger` / `--c-danger-light` / `--c-on-danger`）；
- 复测：`/admin` 1920 浅色、1920 深色、375 深色 **对比度违规 0**（修复前 3 + 1）；
- 说明：采集脚本对「渐变/图片背景」主动跳过，不制造假阴性。

### 3.5 动效设计（8.5/10）

- 四条时间令牌（150/200/350/400ms）与 `cubic-bezier(.4,0,.2,1)`；hover 位移 1px、阴影变化；
- 主题切换前后页面高度 4435px → 4435px（0 跳动，阶段四实测）；
- **扣分点**：未做 DevTools trace 的 60fps 实测，不能仅凭时长合规就给满分。

### 3.6 微交互（9/10）

- `:focus-visible` 统一 2px 品牌色描边（键盘可达）；
- 评分失败可原地重试、成功有 Toast + 目标页指引；删除类操作二次确认（阶段二 P2-20）。

### 3.7 响应式表现（9/10）

| 视口 | 横向溢出 | 触控违规（<48px） |
|---|---|---|
| 375×667 | 0 | **0** |
| 768×1024 | 0 | **0** |
| 1024×768 | 0 | 分页按钮 35px ×6、页脚版本号 24px（见 §6） |
| 1440×900 / 1920×1080 | 0 | 顶部导航 44px（**桌面设计决策**，鼠标精度更高） |

### 3.8 原创性（9/10）

- 设计系统显式列了 6 条反「AI slop」原则（拒绝紫色渐变光晕、网格背景、玻璃态滥用，引入衬线标题、暖色中性、单一强调色）；
- 视觉语言来自「编辑风专业平台」（Notion / Linear / Stripe Docs 的排版逻辑），未复用任何获奖站点模板；
- 局限：这是**设计推导与代码事实**，不是获奖评审结论，不能等同 Awwwards 分数。

## 7. 结论

- 8 维度评分：**7 项 ≥9，动效 8.5（唯一原因是未实测帧率）**；
- 本轮所有修改都由阶段三/四的机器判据驱动，未做「凭感觉换皮」，也未放宽任何门禁；
- 设计体系本身（令牌、容器宽度、断点、语义色）已具备可持续演进的结构，后续优化属于**补充证据与局部打磨**，不需要推翻重来。
