## P1-1 · 回滚窗口僵尸任务（后端）

**现状**：开关关闭时 `AiTaskScheduler.poll()`（`:82`）与 `AiTaskCleanupJob`（`:41-42`）直接 return；
`AiTaskController` 的 `list`（`:136`）/ `cancel`（`:152`）也返 503。
重启时 `@PreDestroy shutdownNow()`（`AiTaskScheduler.java:112-117`）硬杀在途任务 → 该行永久 `RUNNING`，
无人回收（`claimNext` 的 stale 分支被 `!enabled` 挡住），用户看不到也取消不了。

**改什么**
1. `AiTaskController`：`list` / `cancel` **去掉开关闸门**（开关只关「创建」与「调度」）。
2. 新增启动收敛：`ApplicationReadyEvent` 时把 `status='RUNNING' AND lease_until < now()` 的行收敛为
   `QUEUED`（开关开）或 `FAILED + error_code='ROLLBACK'`（开关关）。**不要 DELETE**。
3. 清理任务保持原样（只删有 `finished_at` 的终态行）。

**验收**
- 开关关闭时：`GET /api/tasks` 返回 200 与空列表（不再是 503）；`POST /api/tasks/{id}/cancel` 对 RUNNING 行生效。
- 开关关闭 → 重启 → `SELECT count(*) FROM ai_task WHERE status='RUNNING'` 为 0。
- 开关重开 → 被收敛为 QUEUED 的任务能被正常领取执行。

## P1-2 · 结果不可达（前端，与 P1-3 绑定）

**现状**：出题/评分结果只落 `ai_task.result_text`，唯一出口 `GET /api/tasks/{id}/result` 只在
`utils/serverTask.ts:120-137` 的页内轮询里被调用。`MyTasksDrawer.vue:161-166` 的 `go()` 是裸
`router.push(taskRoute(t.type))`，`myTasks.ts:85-89` 返回 `/interview`（不带 taskId），
`InterviewView.vue:494-499` 的 onMounted 无 taskId 分支。
**更关键**：「建会话 + 题目落库」在 `runServerTask` **返回之后**（`InterviewView.vue:913-935`）——
中途关标签页，业务表根本没写，任务却显示 SUCCEEDED。

**改什么**
1. `taskRoute(type, id)` 支持带 `?taskId=N`（仅 `interview.questions`）。
2. `InterviewView` 挂载时若命中 `taskId`：取 `/api/tasks/{id}/result` → `safeParse` → **复用 `:913-935`
   既有的「建会话 + 题目落库」流程**（不能只塞 `questions.value`，否则会话/题目表仍为空）。
3. 评分链路：结果依附「某道题 + 用户答案」的页内上下文，刷新后上下文已丢 → **先出产品决策**
   （抽屉内渲染版展示 / 不提供「去看看」），不要直接照抄出题的做法。

**验收**：提交出题 → 立刻关标签页 → 从抽屉「去看看」→ 能看到题目，且 `session` 与 `question` 表有对应行。

## P1-3 · 幂等复用 7 天（后端，与 P1-2 绑定）

> ✅ **已按本节方案实现（`d71df1d`）**：后端 `regenerate=true` 掺 UUID、抽屉「重新生成」、面试页用 payload 快照重发。保留原文作为设计依据。

**现状**：`AiTaskStatus.ACTIVE`（`:30`）含 `SUCCEEDED`；`AiTaskService.create`（`:77-83`）按
`userId + idempotencyKey + status in ACTIVE` 复用；`InterviewTaskController:122-124` 的幂等键全由
确定性入参派生（无 nonce）→ 同简历同岗位最长 7 天秒回同一批题，界面无提示、无法重新生成。

**改什么**：幂等键加显式 `regenerate` 标记（前端「重新生成」时传），或在 UI 上明示「复用上次结果」并提供该入口。

**验收**：同简历同岗位第二次请求，可通过显式操作拿到**不同**题目；连点两次（无 regenerate）仍只建一条任务。
