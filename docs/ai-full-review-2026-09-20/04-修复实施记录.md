### 7.5 方法学：如何确认「部署真的生效了」

本项目后端**不暴露版本号或 uptime**（`/api/info` 的 `version` 是写死的 `"1.0.0"`），
因此**不能靠版本号判断部署是否生效**，必须选一个**本次改动引入的、可从外部观测的行为**作为指纹。

两个坑：
1. **推送后立刻探测会误判**。Render 在新版本通过健康检查前**老实例仍在服务**：
   本次 `05:33:11` 探测仍返回 500（旧版），`05:33:25` 部署 success 后才变为 400。
   应先用 `gh api repos/<o>/<r>/deployments` 查部署登记、再查 `/statuses` 看 `state`，最后才探测业务行为。
2. **异常被 `try/catch` 静默吞掉时，指纹要设计成「能区分两条路径」**。
   P3-9 的画像异常会被兜底成「暂无练习数据」而 HTTP 仍是 200，
   故提问设计为「只回答这三个数字」——模型能报出 `0/0/0.0` 就说明走的是新查询路径。
