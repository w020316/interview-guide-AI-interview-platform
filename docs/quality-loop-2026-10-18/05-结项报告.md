## 三、三次"假绿"与一次"假红"

这一段是本次循环最该被复用的部分。

### 3.1 假绿 ①：100 个页面场景全绿，其实在打生产
`vite build` 会把 `.env.local` 的 `VITE_API_BASE_URL` **烧进产物**，本地页面实际在访问线上，
被 CORS 挡住 → 全部空态。**"零溢出零报错"验的是生产 + 空态。**
→ 判据：本地页面检查前 `grep -r onrender.com dist/assets/*.js` 必须为空；改 env 后必须重新 build。

### 3.2 假绿 ②：SPA fallback 让"文件不存在"变成 HTTP 200
抓 chunk 时先拿到的那个名字返回 **index.html（1520 字节）**，`grep` 文案 0 命中，
差点判成"功能没上线"。→ 判据：**看响应体大小与是否含 `<!DOCTYPE`**，真实 JS chunk 是几 KB~几十 KB。

### 3.3 假红：截图看起来有缺陷，DOM 说没有
375px 日历截图里 01–10 号"发灰"、11–17 号"发白"，准备当缺陷上报。
查 computed style 后完全相反：所有本月格子 `rgb(245,245,244)`、`opacity:1` 完全相同。
→ 规则：**截图只用来"发现可疑"，定级前必须回 DOM 验证**。

### 3.4 真实的假绿（这条是缺陷，不是方法问题）
v1.67.0 上线后，未认证调改密接口返回 `400 密码长度不合法` 而不是 `401`。
根因是 Spring Security 的 `AnonymousAuthenticationToken.isAuthenticated()` **恒为 true**、
principal 是字符串 `"anonymousUser"`，而单测用 `@WebMvcTest` **不产生匿名令牌**，所以本地全绿。
→ 规则：**依赖 SecurityContext 判登录态的改动，补测必须显式构造匿名令牌**。

## 五、方法论沉淀（可直接复用到下一个项目）

1. **四层验证**：依赖树 → 打包产物 → 本地全量 → 线上行为。缺任一层都可能假绿。
   （属性写错会静默沿用旧版；部署 success ≠ 应用起得来）
2. **确定性指纹**代替版本号接口：只认"新代码引入的行为差异"（如 400→401、405→404）。
3. **无数据 ≠ 0**：空态一律 `—`/`EMPTY`，禁 `?? 0`；本轮第三次加固。
4. **先 grep 再提建议**：本轮两次把"已存在的功能"（简历对比、求职漏斗）当成缺口，
   根因是凭印象。之后只提两类建议——接口层双向对照出来的缺口，或**没有调用方的死代码**。
5. **门禁是用来遵守的，不是用来绕的**：`border-radius` 写死被拦、changelog 无用户可见内容被拦，
   两次都是**改实现**而不是改断言。

## 六、下一步建议

**短期**：先做 4（依赖）之外任何一件都不划算——因为它们全卡在同一个前提上：要么有 DDL 权限，
要么有额度，要么有管理员账号。这三样都得你给。

**中期**：Boot 3.3 → 4.1 迁移是唯一能一次清掉剩余 20 条 Spring 家族漏洞（含 3C/10H）的路径。
但 3.3 已 EOL 16 个月，4.1 的 EOL 在 2027-07-31，**不急，但不能拖过明年 Q2**。
建议单独排一个迭代，配影子环境 + 全量回归，别和功能开发混在一起。

**长期**：本轮把"能靠代码静态发现的问题"基本扫干净了。剩下的质量风险集中在
**AI 产出质量**（简历分析准不准、面试复盘有没有用）——那需要评测集，不是靠测试能覆盖的。
