## 三、⚠️ 方法学踩坑：第一轮 100 个场景全绿，其实是假的

**现象**：首轮跑完 100 个场景，横向溢出 0，但 **99 个场景有 console error**。

**根因**：构建产物把 API 地址**烧成了生产域名** —— `.env.local` 里写着
`VITE_API_BASE_URL=https://interview-guide-backend.onrender.com`，`vite build` 会读它。
于是本地页面实际在打线上，被 CORS 挡住（`from origin 'http://localhost:4173' has been blocked`），
所有列表都是空态。**这种"全绿"验的是生产 + 空态，不是被测版本的本地形态。**

**处置**：用临时 mode 重建同源产物（`.env.stage3` 里 `VITE_API_BASE_URL=` 置空），
重建后 `grep onrender.com dist/assets/*.js` 为空，再跑才得到 0 报错。

> **判据（建议写进发布流程）**：本地做页面检查前，先确认「页面到底在打谁」——
> `grep -r onrender.com frontend/dist/assets/*.js` 应为空。
> 另外：产物里的 `VITE_API_BASE_URL` 是**构建期**注入的，改 `.env.local` 后必须重新 build，
> 只重启 dev server 不生效。

**副作用说明**：首轮那批请求是 GET（`/api/info`、`/api/resume/history`、`/api/todo/today` 等），
被 CORS 拦在浏览器侧，**没有产生写入**。

## 五、观察（非缺陷，供设计判断）

1. **知识库 tab 换行**：新增第 5 个 tab 后，375px 下 `.tab-switch` 折成 **3 行（2/2/1）**。

4. **404 兜底**：`/this-route-does-not-exist` 正确渲染 404 页，导航栏仍可用。

### 7.4 ⚠️ 一个我差点误报的假阳性（方法论）

看 375px 日历截图时，我判断「01–10 号底色发灰、11–17 号发白，疑似状态样式不一致」，
准备作为缺陷上报。**先查了 DOM 的 computed style，结论完全相反**：

```
01 | -          | rgb(245,245,244) | op=1
15 | has-event  | rgb(245,245,244) | op=1
18 | is-today is-selected | rgb(245,245,244) | op=1
```

所有本月格子的背景色与透明度**逐项相同**，灰白差异是小图缩放下的视觉错觉
（真正的 `is-out` 是 `transparent` + `opacity:0.4`，只作用于相邻月份的那 4 格）。

> **规则**：截图只用来"发现可疑"，**定级前必须回到 DOM / computed style 验证**。
> 否则会把渲染缩放的错觉写成缺陷，浪费一轮修复还可能改坏正确的东西。
